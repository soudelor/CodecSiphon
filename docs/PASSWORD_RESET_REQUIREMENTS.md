# 用户站 — 忘记密码 / 邮箱找回（需求说明）

**技术设计见：[PASSWORD_RESET_TECH_DESIGN.md](./PASSWORD_RESET_TECH_DESIGN.md)。**  
**范围：仅用户站前台**（`/login` 对应体系）；**不包含**管理端独立登录的找回（可二期另立文档）。

---

## 1. 背景与目标

| 项 | 说明 |
|----|------|
| **问题** | 用户忘记密码时无法自助恢复，只能人工处理或重新注册（邮箱唯一时不可行）。 |
| **目标** | 通过**用户注册时使用的邮箱**完成身份核验后，允许用户设置**新密码**并正常使用账号。 |
| **成功标准** | 用户从登录页进入「忘记密码」流程，收到邮件并完成重置后可用新密码登录；未授权第三方无法仅靠猜测邮箱改写他人密码。 |

---

## 2. 用户故事与边界

### 2.1 本期要做

| 编号 | 故事 |
|------|------|
| **FP-01** | 用户在登录页可进入「忘记密码」，输入**邮箱**并提交申请。 |
| **FP-02** | 系统向该邮箱发送**重置指引**（含一次性链接或等价凭证，以实现为准）。 |
| **FP-03** | 用户打开邮件中的链接（或录入邮件中的令牌），填写**符合策略的新密码**并确认后，密码更新成功。 |
| **FP-04** | 重置成功后用户可用**新密码**登录用户站（与现有登录、验证码等行为一致或可配置）。 |

### 2.2 本期不做（可标二期）

| 编号 | 说明 |
|------|------|
| **FP-N01** | 管理端 **`/admin/...`** 的忘记密码（管理员应采用独立运维流程或企业 IdP）。 |
| **FP-N02** | 短信 / Authenticator 等非邮箱二次因子（与邮箱找回正交）。 |
| **FP-N03** | 未经注册的邮箱触发「主动去注册」营销流程（可申请与重置分离）。 |

---

## 3. 功能需求

### 3.1 入口与界面

| 编号 | 需求 | 优先级 |
|------|------|--------|
| **U-01** | 登录页提供「忘记密码」入口，跳转专属页面或同页步骤。 | P0 |
| **U-02** | 「申请重置」页：必填**邮箱**；建议与登录页一致的**图形验证码**（若现有注册/登录已依赖验证码，本产品决策见设计文档 §4）。 | P0 |
| **U-03** | 「设置新密码」页：仅在用户持**有效重置凭证**（链接带 token 或从邮件复制的 code）时可访问；**新密码 + 确认密码**；前端基础一致性校验（长度、两次一致）。 | P0 |
| **U-04** | 全流程文案清晰：**已发送邮件**、**链接已失效**、**重置成功请登录**等；支持现有 i18n（中/英等）。 | P1 |

### 3.2 业务规则

| 编号 | 规则 |
|------|------|
| **B-01** | 仅能向**系统中已存在**且 **用户站可用的账号**发送重置邮件；**不向未注册邮箱透出「是否存在」**（见 **§4 安全与隐私**）。 |
| **B-02** | **已停用账号**（`users.is_active = false`，若已实现 U-05）：与安全策略一致——**不向请求方区分「不存在 / 已停用」**；**可不发送邮件**且不泄露原因。 |
| **B-03** | **邮箱未验证**：若产品上允许未验证邮箱仍视为有效登录账号（与当前实现对齐），则仍允许重置；若以「必须已验证才可重置」为准，则需在产品上明确并联调 `email_verified_at`（首期建议：**不强制邮箱已验证**，与现行注册一致时可降低摩擦）。 |
| **B-04** | 重置成功后：**旧密码立即失效**；**建议**作废该用户既有 **用户站 refresh**（降低被盗会话风险）；是否强制全端登出以技术设计文档为准。 |
| **B-05** | 新密码强度：与 **`register`/现有策略**对齐（最少长度等），避免双线标准。 |

### 3.3 邮件内容（产品侧）

| 编号 | 要求 |
|------|------|
| **M-01** | 邮件说明产品名称、为非回复邮件、重置链接有效期（具体时间由技术设计约定）。 |
| **M-02** | 链接一次性使用说明；若非本人操作忽略等安全提示。 |
| **M-03** | 支持配置「发件人显示名」，避免进入垃圾箱的配置指导放在运维/README（不作需求细则）。 |

## 4. 安全与隐私（强制）

| 编号 | 要求 |
|------|------|
| **S-01** | **防邮箱枚举**：`POST /auth/forgot-password`（名称以设计为准）对**任意合法格式邮箱**返回**统一的 HTTP 响应体结构**（如 `{ "ok": true }`），**不要**区分「未注册」「已停用」等语义。日志与监控层可弱化记录邮箱明文。 |
| **S-02** | **限流**：同一 IP、同一邮箱组合的请求频率需在接入层或服务层限制（阈值见技术设计）；超限返回通用错误或非 200 + 笼统文案。 |
| **S-03** | **重置令牌**：高熵随机、仅存**哈希**、**单次消费**、**过期作废**；禁止在 URL 中长期可预测或复用。 |
| **S-04** | **HTTPS**：生产环境链接必须为 `https`；重置页不得把 token 写入不可信三方脚本。 |

---

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| **NF-可靠性** | 邮件发送失败时：记录错误、可选重试队列；对用户仍表现为 **S-01** 的统一成功响应（可选内部告警）。 |
| **NF-可观测** | 统计重置申请量、成功率、邮件失败率；不包含敏感令牌。 |
| **NF-合规** | 若未来有个人数据合规要求，需登记「重置申请日志」留存周期（首期可仅存必要审计字段或不存明文 token）。 |

---

## 6. 验收清单（概要）

1. 已注册用户完成全流程可登录；错误 token 不可重置。
2. 未注册邮箱与已注册邮箱在申请接口返回值上对用户**不可区分**。
3. 限流触发后不会造成账号状态泄露。
4. 停用账号不暴露状态且无法通过该链路恢复（与设计一致）。
5. 中英文（或仓库已支持的 locale）文案完整、无断头流程。
